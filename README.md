# research-agent

An autonomous research loop that runs on the Claude Code and Codex command-line tools, on the subscriptions you already have. It finds ideas, tries to kill each one with a prior-art search, and tests the survivors with a small build. A different agent then judges the build against tests it wrote before the build started. Every result goes into a records folder of plain Markdown and JSON, so later runs (and other LLMs) can read, combine and build on it.

The loop also tests its own judges. It plants ideas that are known to exist (canaries) and measures how often each agent catches them.

## Why another research agent

Research agents and Claude/Codex orchestrators already exist. This project uses their ideas and credits them below. The gap it fills: a 2026 survey of AI-scientist systems found that 38% run a novelty check, and none tests whether that check is reliable ([arXiv 2608.05179](https://arxiv.org/abs/2608.05179)). This loop measures that reliability directly, with these checks:

- **Canaries.** `loop.py canary` takes an idea that the records already mark as existing, removes its prior art and lessons, and asks each novelty agent about it. `loop.py calibration` prints the catch rate per agent.
- **Two independent novelty checks.** Two agents, ideally from different model families or accounts, search for prior art in separate fresh sessions. The run records whether they agree.
- **Sealed tests.** The referee writes the criteria and the tests before the build. The builder sees the criteria only. The loop hashes the tests and stops the run if they change.
- **Separate roles.** The loop refuses to run if the referee and the builder are the same agent. Agents pass results as files, never through chat, and every call is a fresh session.

## How a run works

1. **Scout** reads `CONTEXT.md` and the existing records, then generates ideas with the bundled `vetted-idea-generation` skill. Ideas that fail the prior-art search go in as `dropped`, with the evidence.
2. **Novelty** checks run in two agents.
3. **Referee** writes `criteria.md`, `holdout.md` and pytest tests.
4. **Builder** builds the smallest version that meets the criteria and writes `REPORT.md`.
5. **Referee** checks the seal, runs its tests, reproduces the result and writes `verdict.json`.
6. **Record**: the loop appends a dated line to the idea, sets its status, rebuilds `INDEX.md` and `graph.json`, and commits the records repo.

`loop.py auto <cycles>` repeats this unattended. Each cycle runs the scout if fewer than 2 ideas wait, then tests the oldest untested idea. Every third cycle adds a canary. A failed run parks its idea and the loop goes on.

## Setup

1. Install [Claude Code](https://code.claude.com) and log in.
2. Optional, a second Claude account for the referee. In PowerShell:
   ```
   $env:CLAUDE_CONFIG_DIR = "$HOME\.claude-b"
   claude
   ```
   Run `/login` with the second account, then exit. On macOS or Linux use `CLAUDE_CONFIG_DIR=~/.claude-b claude`.
3. Optional, Codex: `npm install -g @openai/codex`, then `codex login`. Set a role to `codex` in `config.json`. If Codex is missing, those roles fall back to `claude-b`. The Codex call is not tested yet.
4. Copy `config.example.json` to `config.json`. Set `records` to the folder for your outputs, ideally a private git repo.
5. Run `py loop.py init`, then edit `CONTEXT.md` in the records folder.

## Use

```
py loop.py scout "nowcasting regional activity with free data"
py loop.py run <idea-id>
py loop.py canary 3
py loop.py calibration
py loop.py auto 5
```

## Records layout

| Path | What it holds |
|---|---|
| `CONTEXT.md` | Goals, topics, your edge and the rules. The scout and referee read it. |
| `ideas/<id>.md` | One idea: front matter (status, problems, links), then problem, idea, prior art, progress, lessons |
| `INDEX.md`, `graph.json` | Generated by `records.py`: ideas by status, shared problems, links between ideas |
| `runs/<date>-<id>/` | Each agent's novelty verdict, the referee's sealed tests, the build, the verdict, `result.json` |
| `calibration.csv` | One row per canary per agent: caught or not |

## Rules and limits

- Builders use free, public data only. Never give the loop licensed or private data, or credentials.
- Anthropic allows `claude -p` in your own scripts. It does not allow third-party tools to use your subscription login. Scripted use may count against a separate monthly credit pool. Check the current terms for your plan. Use one account per person. Do not share or resell access.
- The builder works in its own folder, and the sealed tests sit outside it. The seal catches edits, but a determined builder could still read the tests from disk. Use a container if that matters.
- The builder can run Python. Run the loop on a machine and account where that is acceptable.
